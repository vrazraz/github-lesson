От нуля до проекта в GitHub.

Вы конечно можете и сами все это прочитать, но не захотите, потому что такой формат подачи не всем подходит. Многим из вас гораздо легче попробовать на практике совместно. Собственно мы за этим и здесь...

Что получится в конце

У вас будет ссылка на аккуратный репозиторий с проектом, понятной историей изменений и списком задач, который удобно показать команде.

Не учим программирование

GitHub здесь — рабочая папка проекта и история решений, а не экзамен по коду.

Работаем маленькими шагами

Один заметный результат — один коммит. Так легко понять, что изменилось.

Обсуждаем через Issues

Issue — карточка задачи, вопроса или найденной проблемы.

GitHub на человеческом языке

Repository / репозиторий

Онлайн-папка проекта и его история. Можно представить как файл кейса, к которому добавили версии и обсуждения.

Commit / коммит

Зафиксированное изменение. Как «сохранить версию» в Figma, только с короткой подписью и историей.

Issue

Карточка задачи, вопроса или бага. У неё есть название, описание, статус и обсуждение.

Branch / ветка

Отдельная линия работы. Для начала можно работать в основной ветке; отдельные ветки понадобятся при командной работе.

Pull request

Предложение добавить изменения из одной ветки в другую. Команда просматривает и обсуждает правки, а затем объединяет ветки. В первом уроке Pull request не нужен — он пригодится для командной работы.

README

Главная инструкция проекта. Это первый экран, который читает человек, открывший репозиторий.

Public / Private

Public виден всем по ссылке. Private доступен только вам и приглашённым участникам.

Основной маршрут

8 шагов до публикации

В уроке используются названия действий GitHub и один реальный скриншот. Если интерфейс обновился, ориентируйтесь на подписи кнопок.

  1. Создайте аккаунт GitHub

    Цель: получить личный профиль, от имени которого будут видны проекты и изменения.

    Откройте github.com/signup и заполните короткую форму:

    1. Электронная почта. GitHub пришлёт письмо для подтверждения.
    2. Пароль. Используйте уникальный пароль и сохраните его в менеджере паролей.
    3. Имя пользователя. Оно станет частью публичного адреса профиля, поэтому выберите спокойное профессиональное имя.

    Готово, если вы вошли в GitHub и видите свой аватар в правом верхнем углу.

  2. Подтвердите email и настройте профиль

    Цель: чтобы коллеги понимали, кто владелец проекта.

    Перейдите по письму подтверждения. Затем добавьте имя и, по желанию, фото. Не публикуйте в профиле личные секреты, токены или пароли.

    Подсказка дизайнера

    Используйте тот же username, который удобно произнести вслух и вставить в портфолио.

  3. Создайте репозиторий

    Цель: завести онлайн-папку для проекта.

    Нажмите + → New repository. Введите название без пробелов, например portfolio-case-study. Добавьте короткое описание. Для первого публичного учебного проекта выберите Public. Включите Add a README file.

    Важно: не кладите в Public-репозиторий пароли, API-ключи, персональные данные клиентов и закрытые макеты.

  4. Подготовьте проект к загрузке

    Цель: сделать папку понятной для другого человека.

    В корне проекта положите файл README.md с ответами: что это, для кого, как открыть, какие решения вы приняли. Для ссылок на Figma используйте доступ «Anyone with the link can view» — только если это безопасно.

    # Название проекта

Коротко: что это и какую проблему решает.

## Ссылка на прототип
[Открыть в Figma](https://figma.com/...)

## Моя роль
Исследование · структура · UI · тестирование

  5. Загрузите файлы проекта

    Цель: увидеть проект в репозитории, а не только на компьютере.

    Выберите один способ. Если сомневаетесь, начните с интерфейса GitHub. Терминал и агент — альтернативы, их не нужно выполнять после способа 5.1.

    Рекомендуемый способ для первого урока
    1. На странице репозитория нажмите Add file → Upload files.
    2. Перетащите нужные файлы или папку.
    3. В поле сообщения напишите результат, например: Добавил первый экран и README.
    4. Нажмите Commit changes.

    Готово, если файлы появились на странице репозитория.

    Альтернатива · нужен установленный Git

    Скопируйте URL репозитория на GitHub и выполните команды в терминале. После клонирования перенесите файлы проекта в созданную папку, затем проверьте и отправьте изменения.

    git clone <URL-репозитория>
cd <папка-репозитория>
git status
git add .
git commit -m "Добавил файлы проекта"
git push

    Перед git add проверьте git status: в списке не должно быть паролей, токенов и закрытых данных.

    Альтернатива · агент должен видеть папку и иметь доступ к GitHub

    Откройте папку проекта в агенте и дайте ему конкретное задание.

    Пример задания

    Проверь файлы проекта и покажи, что попадёт в репозиторий. Не добавляй пароли, токены и закрытые данные. После моего подтверждения создай коммит «Добавил файлы проекта» и отправь изменения на GitHub.

    Перед подтверждением проверьте список файлов, изменения и текст коммита. Если агент не авторизован в GitHub, выполните вход сами.

  6. Проверьте сообщение коммита

    Цель: оставить в истории короткую и понятную запись о результате.

    Каждый способ из шага 5 уже создаёт коммит. Не делайте новый коммит без изменений: проверьте созданное сообщение и используйте правило для следующей загрузки.

    Формула

    Глагол + объект: «Обновил описание кейса» или «Добавил мобильный сценарий».

    Слабо: update, fix, новые файлы

    Понятно: Добавил README и обложку кейса

  7. Заведите Issues для задач

    Цель: не держать идеи и проблемы в голове или в случайном чате.

    Откройте вкладку Issues → New issue. Название делайте конкретным: «Проверить контраст кнопки на мобильном». В описании добавьте контекст, шаги и критерий готовности.

    Название: Проверить контраст кнопки на мобильном

    Контекст: На экране оплаты проверить кнопку в светлой теме.

    Готово, если: контраст текста соответствует WCAG AA.

    Добавьте три Issue: задачу, вопрос и найденную проблему. Закрывайте Issue после проверки результата.

  8. Опубликуйте и поделитесь проектом

    Цель: дать команде одну понятную точку входа.

    Скопируйте URL репозитория из адресной строки. Проверьте его в приватном окне браузера: открывается ли README, понятны ли изображения и доступна ли ссылка на Figma. В резюме или портфолио добавьте 1–2 предложения о своей роли.

    Финальная проверка

    Ссылка должна вести не на отдельный файл, а на страницу репозитория. Так человек увидит контекст, структуру и историю изменений.

Частые вопросы

Нужно ли устанавливать Git?

Для основного способа через сайт — нет. Git понадобится, только если вы выберете вкладку «5.2 Терминал».

Можно ли сделать репозиторий Private?

Да. Это правильный выбор для NDA, клиентских материалов и незапущенных продуктов.

Что делать, если загрузка не работает?

Проверьте размер файлов и интернет. Не загружайте тяжёлые видео и исходники макетов без необходимости. Скопируйте текст ошибки: по нему проще найти решение.

Коммит — это публикация?

Коммит сохраняет изменение в истории. Публикация проекта — это когда вы отправляете другим ссылку на репозиторий или отдельно включаете GitHub Pages.
